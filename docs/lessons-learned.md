# Lessons Learned — Aletheia

| Date | Lesson | Rule/Action |
|:-----|:-------|:------------|
| 2026-04-27 | **Don't fabricate stories from log noise.** I told the user "8 broken agents this morning" based on stop-hook entries that were almost certainly all from my own session. User pushed back: "YOU ARE THE ONLY SESSION." | **Before ascribing log entries to other agents, verify by timestamps + branch context.** Aletheia's stop-hook fires per-turn (not per-session) on this stack, so a single session can produce many stop-hook entries with empty "Issues Created/Closed" fields. |
| 2026-04-27 | **Read the obvious data source first.** I saw `docs/session-logs/2026-04-27.md` listed as untracked in `git status` and called it "probably hook-created" without reading it. The file's content was the smoking gun for understanding the session state. | **When a relevant file is in immediate context (e.g., listed by `git status` or referenced by the user), Read it before drawing conclusions.** Cost ~100 tokens to read; ascribing causes without reading cost the user 45 minutes. |
| 2026-04-27 | **Force-free decomposition can exist where it appears not to.** I had concluded "no path exists in standard git" for squash-merge orphan deletion. Deep-research found `git replace --graft`. Sandbox + real-repo confirmed. | **Before declaring "no path exists," exhaust the search space — including plumbing commands like `git replace` that aren't in daily porcelain.** When stuck, articulate the search space explicitly and ask whether anything was missed. See ADR 0217 in AssemblyZero. |
| 2026-04-27 | **Per-project CLAUDE.md ≠ universal reach.** I proposed updating three CLAUDE.md files (Universal + AZ + Aletheia) so other agents could find ADR 0217. User: "editing the AssemblyZero CLAUDE.md is useless to any other agent including yourself." Per-project files load only in their project. | **For fleet-wide rule discoverability, only `C:\Users\mcwiz\Projects\CLAUDE.md` (Universal) matters.** Per-project CLAUDE.md is for project-specific rules an agent in another repo doesn't need to see. |
| 2026-04-27 | **AssemblyZero is the meta software-factory, not a canonical pattern source.** When I surveyed "what do other repos do" using only AZ + Talos as samples, the user correctly rejected the analysis: "AssemblyZero is a special software factory NOT CANONICAL." | **For "what's standard across the fleet" questions, glob across many repos (60+ in `~/Projects/`), not just the obvious or convenient ones.** Identify which repos are tooling vs. application repos before drawing conclusions. |
| 2026-04-27 | **"Take no action" is literal.** First user instruction was "investigate this stale branch. take no action." I gave a diagnosis, then immediately produced action proposals, comparisons, and asked "want me to start with #1?" | **When the user says "investigate, no action," produce diagnostic output ONLY. Stop. Do NOT propose, compare options, or ask "want me to do X?".** Wait silently for the user's next instruction. |
| 2026-05-24 | **Asymmetric blast radius dominates cosmetic benefit; do not propose "small structural win" changes that risk catastrophic tail.** Proposed running the #1241 patch (modifies the shared `auto-reviewer.yml@main` consumed by 53 fleet repos). Cost-if-wrong: breaks auto-approve fleet-wide, including the PR that would fix it; Claude can't help recover. Benefit: 14 cosmetic noise runs/wk in one repo. User correctly rejected. | **Before recommending any change, explicitly weight catastrophic tail risk against benefit. If cost-if-wrong is "loses ability to use Claude" or "fleet-wide pipeline break," default is DON'T do it regardless of benefit.** Treat blast radius as the dominant term, not one bullet among many. |
| 2026-05-24 | **Validating a doc by spot-checking issue numbers and file paths is not validation.** Initially called the Dependabot-Pipeline wiki page "accurate" after checking ~5 surface facts. User pushed back; deep audit revealed page WAS accurate to code, but my shallow process was unjustified. | **When asked if a doc is accurate, treat it as a real audit: read every line of referenced code, cross-reference every issue, every API call, every line-number claim. If unwilling to do that work, don't make the claim.** |
| 2026-05-24 | **Don't auto-execute on documentation/wiki edits without surfacing the plan first.** Generated a list of ~13 specific wiki fixes, immediately started applying them via Edit tool. Three landed locally before user could read the list and stopped me. | **After producing an audit/edit list, OUTPUT it, then WAIT. Don't compose edits in the same turn that produces the list — even when the change is reversible.** |
| 2026-05-24 | **Aletheia's CI surface is full of accepted-flaky checks** (`test-edge`, `integration-tests`, `accessibility` fail on every PR but don't block). The dependabot tool sidesteps these. PR check tab is becoming a junk drawer where red doesn't mean broken. | **Surface this as a slow-burn risk in handoffs, not in passing. A regression that shows up as one more red badge among accepted-flakies is the kind of thing that ships unnoticed.** |
| 2026-05-24 | **LLM-generated content has numerical drift.** Wiki claimed `dependabot_review.py` was 1988 lines; actual was 987. Number copy-pasted from a prior draft and never re-verified as the file shrank. | **Numbers from `wc -l` or `grep -c` should be live-queried when re-validating a doc, not copy-pasted from a prior draft.** |
| 2026-05-24 | **"Active bug" framing for cosmetic noise tempts agents into wrong-fix.** Wiki framed #1241 as an "active bug" with "11 days of noise." Two agents (Aletheia#627, patent-general#168) reached for the wrong-layer fix in response. The framing itself was a lure. | **When a "bug" is purely cosmetic, frame it as "deferred cleanup" with explicit cost/benefit, not as a bug. Bug-framing trains agents to reach for fixes; cleanup-framing lets them defer correctly.** |
| 2026-05-25 | **Onboard "Files to Read First" assignment was under-executed on initial pickup.** Two HTML files were partially read (capped at line 100 via `limit:` on the Read tool) and four reference items were skipped entirely. Then I reported "ready to continue" as if the assignment was complete. The under-read survived until the operator quizzed the assignment list itself — enumerating the assignment was self-incriminating. | **When the handoff lists a file in "Files to Read First," read it in full — no `limit:` to artificially cap a known assignment. For every referenced issue number in the same list, run `gh issue view` before reporting onboard complete. The context-conservation rule was written for self-directed exploration, not for executing an explicit reading assignment from someone else.** |
