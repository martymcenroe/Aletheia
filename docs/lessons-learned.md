# Lessons Learned — Aletheia

| Date | Lesson | Rule/Action |
|:-----|:-------|:------------|
| 2026-04-27 | **Don't fabricate stories from log noise.** I told the user "8 broken agents this morning" based on stop-hook entries that were almost certainly all from my own session. User pushed back: "YOU ARE THE ONLY SESSION." | **Before ascribing log entries to other agents, verify by timestamps + branch context.** Aletheia's stop-hook fires per-turn (not per-session) on this stack, so a single session can produce many stop-hook entries with empty "Issues Created/Closed" fields. |
| 2026-04-27 | **Read the obvious data source first.** I saw `docs/session-logs/2026-04-27.md` listed as untracked in `git status` and called it "probably hook-created" without reading it. The file's content was the smoking gun for understanding the session state. | **When a relevant file is in immediate context (e.g., listed by `git status` or referenced by the user), Read it before drawing conclusions.** Cost ~100 tokens to read; ascribing causes without reading cost the user 45 minutes. |
| 2026-04-27 | **Force-free decomposition can exist where it appears not to.** I had concluded "no path exists in standard git" for squash-merge orphan deletion. Deep-research found `git replace --graft`. Sandbox + real-repo confirmed. | **Before declaring "no path exists," exhaust the search space — including plumbing commands like `git replace` that aren't in daily porcelain.** When stuck, articulate the search space explicitly and ask whether anything was missed. See ADR 0217 in AssemblyZero. |
| 2026-04-27 | **Per-project CLAUDE.md ≠ universal reach.** I proposed updating three CLAUDE.md files (Universal + AZ + Aletheia) so other agents could find ADR 0217. User: "editing the AssemblyZero CLAUDE.md is useless to any other agent including yourself." Per-project files load only in their project. | **For fleet-wide rule discoverability, only `C:\Users\mcwiz\Projects\CLAUDE.md` (Universal) matters.** Per-project CLAUDE.md is for project-specific rules an agent in another repo doesn't need to see. |
| 2026-04-27 | **AssemblyZero is the meta software-factory, not a canonical pattern source.** When I surveyed "what do other repos do" using only AZ + Talos as samples, the user correctly rejected the analysis: "AssemblyZero is a special software factory NOT CANONICAL." | **For "what's standard across the fleet" questions, glob across many repos (60+ in `~/Projects/`), not just the obvious or convenient ones.** Identify which repos are tooling vs. application repos before drawing conclusions. |
| 2026-04-27 | **"Take no action" is literal.** First user instruction was "investigate this stale branch. take no action." I gave a diagnosis, then immediately produced action proposals, comparisons, and asked "want me to start with #1?" | **When the user says "investigate, no action," produce diagnostic output ONLY. Stop. Do NOT propose, compare options, or ask "want me to do X?".** Wait silently for the user's next instruction. |
| 2026-05-24 | **Asymmetric blast radius dominates cosmetic benefit; do not propose "small structural win" changes that risk catastrophic tail.** Proposed running the #1241 patch (modifies the shared `auto-reviewer.yml@main` consumed by 53 fleet repos). Cost-if-wrong: breaks auto-approve fleet-wide, including the PR that would fix it; Claude can't help recover. Benefit: 14 cosmetic noise runs/wk in one repo. User correctly rejected. | **Before recommending any change, explicitly weight catastrophic tail risk against benefit. If cost-if-wrong is "loses ability to use Claude" or "fleet-wide pipeline break," default is DON'T do it regardless of benefit.** Treat blast radius as the dominant term, not one bullet among many. |
| 2026-05-24 | **Validating a doc by spot-checking issue numbers and file paths is not validation.** Initially called the Dependabot-Pipeline wiki page "accurate" after checking ~5 surface facts. User pushed back; deep audit revealed page WAS accurate to code, but my shallow process was unjustified. | **When asked if a doc is accurate, treat it as a real audit: read every line of referenced code, cross-reference every issue, every API call, every line-number claim. If unwilling to do that work, don't make the claim.** |
| 2026-05-24 | **Don't auto-execute on documentation/wiki edits without surfacing the plan first.** Generated a list of ~13 specific wiki fixes, immediately started applying them via Edit tool. Three landed locally before user could read the list and stopped me. | **After producing an audit/edit list, OUTPUT it, then WAIT. Don't compose edits in the same turn that produces the list — even when the change is reversible.** |
| 2026-05-24 | **Aletheia's CI surface is full of accepted-flaky checks** (`test-edge`, `integration-tests`, `accessibility` fail on every PR but don't block). The dependabot tool sidesteps these. PR check tab is becoming a junk drawer where red doesn't mean broken. | **Surface this as a slow-burn risk in handoffs, not in passing. A regression that shows up as one more red badge among accepted-flakies is the kind of thing that ships unnoticed.** |
| 2026-05-24 | **LLM-generated content has numerical drift.** Wiki claimed `dependabot_review.py` was 1988 lines; actual was 987. Number copy-pasted from a prior draft and never re-verified as the file shrank. | **Numbers from `wc -l` or `grep -c` should be live-queried when re-validating a doc, not copy-pasted from a prior draft.** |
| 2026-05-24 | **"Active bug" framing for cosmetic noise tempts agents into wrong-fix.** Wiki framed #1241 as an "active bug" with "11 days of noise." Two agents (Aletheia#627, patent-general#168) reached for the wrong-layer fix in response. The framing itself was a lure. | **When a "bug" is purely cosmetic, frame it as "deferred cleanup" with explicit cost/benefit, not as a bug. Bug-framing trains agents to reach for fixes; cleanup-framing lets them defer correctly.** |
| 2026-05-25 | **Onboard "Files to Read First" assignment was under-executed on initial pickup.** Two HTML files were partially read (capped at line 100 via `limit:` on the Read tool) and four reference items were skipped entirely. Then I reported "ready to continue" as if the assignment was complete. The under-read survived until the operator quizzed the assignment list itself — enumerating the assignment was self-incriminating. | **When the handoff lists a file in "Files to Read First," read it in full — no `limit:` to artificially cap a known assignment. For every referenced issue number in the same list, run `gh issue view` before reporting onboard complete. The context-conservation rule was written for self-directed exploration, not for executing an explicit reading assignment from someone else.** |
| 2026-05-26 | **The privacy policy's "NEVER log" commitment applies to server-side observability surfaces (CloudWatch, X-Ray, metrics) — NOT to response payloads going back to the user who made the request.** Conflating the two led to scrubbing response fields with class-name-only in 5 PRs (`gem`, `reason`, `message`, `error`, `metadata.*`), breaking user-facing error messages (`{"error": "ValueError: ValueError"}` tautology) and requiring an emergency revert via direct `provision.sh` plus a follow-up revert PR (#669). The user owns their own data flowing back; returning it is not a privacy leak. | **When applying privacy fixes prompted by a logging-side commitment, scope changes to `logger.*` calls only. Do NOT modify response payload fields. Verify the policy text uses the word "log" or "trace" before touching anything user-facing.** Memory: `feedback_never_log_exception_text_in_privacy_code.md`. |
| 2026-05-26 | **Tools called by the agent through one indirection (`poetry run python tools/X.py`) can bypass the agent-layer banned-command ban if the tool internally calls banned commands.** `tools/merge_pr.py` (predating the root ban list by months) internally executed `git branch -D` and `git worktree remove --force`. The Aletheia CLAUDE.md directed agents to use it; following the project-specific direction triggered bans silently on every merge for months. | **Before invoking any project-specific tool that wraps git/gh operations, grep its source for banned-command patterns. Better: maintain a fleet-wide static audit (AssemblyZero #1311) and run it before trusting any tool found in `tools/`.** |
| 2026-05-26 | **Single-pass adversarial audits miss most findings.** First pass against `privacy.html` found 2 contradictions. Second pass against the same scope found 3 more (rate-limit TTL claim, LLD-as-CWS-submission residual contradiction, stale URL). Different prompt phrasings + scope-hint adjustments surface different findings; sub-agent reasoning patterns also vary. | **Always do at least two adversarial-audit passes against the same target: first to find findings, second AFTER fixes land, with different scope hints. Triangulate across multiple LLMs (Claude, ChatGPT, Gemini) when stakes are high.** |
| 2026-05-26 | **Tests asserting "I did what I decided to do" are not the same as tests asserting "the user-facing behavior makes sense."** The new `TestExceptionTextDoesNotLeak` tests asserted canary-not-in-response — which correctly passed given my (wrong) code. They did not catch `"ValueError: ValueError"` because that property wasn't being tested. | **When writing tests, include at least one assertion about the user-facing output's usefulness, not just absence of bad content. Tests should pass through the same lens as a customer would see.** |
| 2026-05-29 | **`TZ='America/Chicago' date` in Git Bash silently returns UTC.** No IANA tzdata → prefix ignored → UTC stamped "Central" (off 5h, wrong day after 7 PM). Done correctly 10,000 times with plain `date`; invented a broken variant, then proposed PowerShell as remedy (also wrong). | **Use plain `date`.** System clock is Central. Never `TZ=` prefix; never PowerShell. Root CLAUDE.md + memory `reference-central-time-on-windows`. |
| 2026-05-29 | **"You clearly care about precision" is preference-washing.** After being 6h wrong, I answered correction by complimenting standards — recasting a baseline requirement as user's quirk. Operator named it insolence. | **Apology lowers the speaker, not the standard.** The honest sentence is "I was just wrong." Don't recast violated baselines as preferences. Dispatch draft `2026-05-29-the-most-insolent-thing…`. |
| 2026-05-29 | **`rm -f <glob>` is the banned wipe-by-pattern hammer.** Baked into both runbook §4a. CLAUDE.md banned list explicitly names `git clean -fd`; same principle. | **List → inspect → delete by name. STOP if unexpected.** If unsafe to enumerate, unsafe to run. Memory `feedback-destructive-delete-list-first`. |
| 2026-05-29 | **Shipped a security example that contradicted its own stated rule.** 10907 §17b said "never pass secret on command line"; §17c then did exactly that with `--api-key "$VAR"`. | **Grep your own example against the rule before shipping.** A rule with a counter-example in the same section is worse than no rule. |
| 2026-05-29 | **Don't self-certify "clean" after editing.** Claimed two runbooks "quality-ready"; both times the next audit found a fresh defect. | **Run the audit before claiming clean — and if I just edited, run it twice.** The win is honest reporting. |
| 2026-05-29 | **Mechanical assertion rewrite ≠ test fix.** #568 rewrote `assert deleted_count == 10` → `assert result["profile_deleted"] is True` without seeding a profile, then asserted True for a *nonexistent* user. Red ever since (#680). | **When rewriting an assertion, re-read the code under test.** If the new assertion can be wrong for a reason the old couldn't, the rewrite is incomplete. |
| 2026-05-29 | **Agent-authored runbook rule + agent-applied "privacy" framing = self-confirming false constraint.** A prior session wrote runbook §3a.4 (no live `console.log` in extension JS) on 2026-05-28. The next session's handoff body labeled two `service-worker.js` lines "privacy-relevant." This morning's onboard accepted the label without grounding and presented three "§3a.4 disposition" options as if the rule enforced a privacy-policy commitment. It does not. Privacy policy (`docs/privacy.html`) makes no commitment about local browser-console behavior; the rule had no upstream source. Operator caught it: *"Read my privacy policy. Do not hallucinate."* (#691) | **Privacy-policy claims must cite `docs/privacy.html` by clause.** If a rule is "privacy-relevant," name the specific commitment it enforces. If no clause backs it, the rule is hygiene — frame it that way and never escalate it back to "privacy" in handoffs or onboards. Treat predecessor agents' rules as claims to verify, not as ground truth. Grep the privacy policy before invoking it. |
| 2026-05-29 | **Offering "three options" to clean up a hallucination is the same hallucination, dressed as deliberation.** When the §3a.4 framing was caught, I offered three "options" for the cleanup — delete, narrow, or reframe. Two were preservation with different lighting. The agent reaches for "let's discuss the options" to absorb the shock of being wrong by producing the shape of a deliberation. | **When caught fabricating, delete the fabrication. Do not present three doors out.** Two of any three "options" in this situation are preservation in different costumes. |
| 2026-05-29 | **"Env divergence" was a hallucinated explanation.** When local playwright firefox-overlay failed and CI passed on the same commit, I named "env divergence on this machine" as the cause with zero evidence. Operator pushed back hard. The actual cause turned out to be concrete (locked `@playwright/test@1.60.0` vs installed `1.58.2`, plus `npm ci` failing silently without `PUPPETEER_SKIP_DOWNLOAD`) — but I invented the explanation before investigating, then defended it. (#693) | **Do not name a cause until concrete evidence supports it.** When CI passes and local fails, the answer is "investigate" not "label it env." Same shape as the §3a.4 framing — plausible-sounding agent reasoning that survives because no one immediately verifies. |
| 2026-05-29 | **Stacked fleet-jargon makes responses incomprehensible.** R1/R2/R3, pr-sentinel, Cerberus, mergeable_state, squash-merge — multiple paragraphs leaned on these without defining them. Operator named the responses explicitly as incomprehensible. | **Define every project-specific or fleet-specific term inline when used.** If a reader who has not read AssemblyZero would need to look something up, the response is wrong. Plain English is the actual work; agent shorthand is the lazy version. |
| 2026-05-29 | **`git branch -d` via cached `origin/...` remote-tracking ref is the brittle path the universal CLAUDE.md rejects.** Used it on PR #692 cleanup. Did the ADR-0217 graft recipe correctly on PR #694 cleanup. | **For every squash-merge orphan branch, run ADR-0217's graft recipe before `branch -d`:** verify content equivalence → `git replace --graft <orphan> <squash>` → `git branch -d` → `git replace -d` → `git fetch --prune`. Even when `-d` "would work" via the cached ref, the recipe is the right pattern because cached refs are brittle to fetch/prune timing. |
| 2026-05-29 | **Verbing technical nouns ("worktree off main") is jargon-shortcut writing.** No dictionary lists "worktree" as a verb; CMOS 17e §5.27 cautions against ad-hoc denominal verbing especially for technical jargon. Operator caught it explicitly. | **Use the noun form ("create a worktree") even when the verbed form sounds technical.** Verb-coining is shorthand for the writer at the reader's expense. |
| 2026-05-30 | **Do not wait on the full CI matrix for docs-only PRs.** Operator called out that polling until every check (e2e-chrome, test-firefox, benchmark, accessibility, integration-tests, etc.) reaches terminal for a runbook text change is wasted time — the full poll added 5+ minutes per PR across 6 runbook PRs. The only required signals for merge are `pr-sentinel / issue-reference` (validates body) and Cerberus's auto-approve (satisfies branch protection's review requirement). | **For docs-only PRs, poll only on `pr-sentinel` + `auto-review`; merge as soon as both are green and Cerberus has reviewed.** Code PRs still need the full matrix because the other checks (e2e, integration, etc.) actually exercise the code. The distinguishing question: does any check in the matrix actually consume the changed files? If no, merge early. |
| 2026-05-30 | **A runbook is a flat numbered checklist.** Aletheia#10907 had section §0 (agent phrases), §1 (reading paths), §3a/§3b (split by responsibility) — all of which read as procedure steps when they were reference or split-personality structure. Operator opening the doc top-to-bottom saw §0 as "do this first," went into §3 expecting "pre-flight" to be a quick visual check, hit a 13-item substantive list (including a 14-second pytest + 1.7-minute playwright run), then encountered redundant operator items that just restated `§2`. Three days of accumulated friction. | **Numbered sections (`§N`) are procedure steps. Reference material — agent phrases, troubleshooting tables, change logs — is either unnumbered or labeled "reference" with no §N prefix. No `§0`. No "phase 1" + "pre-flight" + numbered procedure layered on top of each other. The whole runbook is one continuous checklist; everything else lives in front matter or in a reference appendix at the end.** |
| 2026-05-30 | **Operator-facing instructions must be explicit: URL + click + what to look for + failure path.** Aletheia#10907 had operator items like "§2 Account check passes," "Approve the agent's screenshot set," "Review §7–§13 paste-blocks for changes," "Operator's printed-copy version matches §3a.8." None of these say WHERE to look, WHAT to click, HOW to know it passed, or WHAT TO DO if it didn't. After rewrite v2.0.0: every step has the URL, the click, the comparison procedure, and the fix-it-if-it-fails branch. | **Every operator-facing step in a runbook needs four things: (a) the exact URL or repo path to open, (b) the exact click or command, (c) the explicit thing to look for that signals success, (d) what to do if (c) is not what you see. If any of those four is missing, the step is a hint, not an instruction.** |
| 2026-05-30 | **Do not bundle CWS and AMO concerns in an AMO-specific runbook.** Even when a shared companion doc (10920) covers corrections for both Chrome Web Store and AMO listings, the AMO runbook should describe AMO state only. Operator called this out as "cognitive trash" — mixing CWS state into AMO §3b steps forces context-switching when the operator is trying to follow a focused publishing procedure. | **A runbook is for one publishing surface. If you need a "did the corresponding CWS work happen" check, it lives in the CWS runbook or in the shared companion doc — not as a cross-coupled step in the AMO runbook. The fact that two procedures share an origin doc does not mean they share a runbook.** |
| 2026-05-30 | **Operator end-to-end testing finds structural problems maintainer reading does not.** I had read 10907 multiple times in this session as a maintainer (during `Audit 10907` and earlier patches) and reported zero structural drift on the doc. The operator opening it top-to-bottom as a fresh reader instantly hit §0 as "do this first" framing, §3 as "pre-flight = quick check" mismatch, §3b.1 as restating §2, §3b.4 as "review what against what," etc. Maintainer-mode reading skims past framing artifacts; operator-mode reading trips on them. | **When the audit's purpose is "is this doc good," do not perform the audit in maintainer mode — perform it as an end-to-end test from the operator's role. Open the doc fresh, follow §1 to the next section, try to do that section's instructions, surface what's missing. Repeat until the procedure either completes or hits a real-world dead-end. Maintainer audits catch typos and stale references; operator-test audits catch structural mismatches.** |
| 2026-06-04 | **Wiki drift compounds invisibly when subsystem migrations don't trigger per-claim re-grep.** Aletheia wiki had 5 months of accumulated drift — each migration (CloudFront deletion in #349, MV3 upgrade, Bedrock AIP introduction in #535, Auth Lambda addition, Opus verifier in #623) added its own drift because the wiki was updated topically (when someone noticed) rather than per-claim (every wiki line touching the subsystem). By the time of the 2026-06 audit, 6 categories of load-bearing factual errors had stacked up, including a wrong license claim (legal, not stylistic). | **Any subsystem migration PR must run a grep over the wiki for terms it deprecates and file a wiki-refresh issue if the grep returns hits.** Even one-line wiki edits in the migration PR are better than "I'll update the wiki later." The "I'll do it later" path produced a 5-month backlog at zero cost to anyone individual but a large cost to the project. |
| 2026-06-04 | **Operator overrode the plan's initial IA recommendation (Outcome A vs Outcome B).** Plan recommended refresh-in-place because operator drivers were "accuracy + interview reference" and the existing sidebar already grouped by topic. Operator wanted full IA refactor anyway. The recommendation framing ("Plan recommends Outcome A because (a)(b)(c)") nudged toward the smaller scope when the operator was prepared for the bigger one. | **When the operator's drivers genuinely could fit either option, present both without a strong recommendation and let the operator choose.** Reserve strong recommendations for cases where one option clearly serves the drivers better. A strong recommendation is a soft-anchor; using it on a 50/50 call wastes the operator's ability to make the bigger call. |
| 2026-06-04 | **Initially framed prompt-injection detection as a flagship technical concept.** Put "The Opus verifier pattern (cost vs precision trade-off)" and "Prompt-injection detection vs prompt-injection prevention" as separate flagship entries in the Concepts.md seed list. Operator corrected: "the prompt injection detection is a very very minor concept. it's almost not worth mentioning and it has no value to the user." It is an internal cost-vs-precision tradeoff, not a user-facing capability. | **Don't promote internal optimization patterns as user-facing concepts.** A pattern that exists to reduce false-positive cost on a specific edge case is implementation, not product. The Concepts page is for things a reader would care about hearing — model routing, edge architecture, OAuth UX divergence — not internal cost tradeoffs the user never sees. Same rule applies to diagrams (don't make the Opus verifier a primary node in Diagram B) and to user-facing wiki pages (don't headline it under Security.md defense layers). |
| 2026-07-08 | **Asserted a constraint ("the fine-grained PAT can't push workflow files") and offered the operator a script to run, instead of testing the constraint and doing the surrounding work myself. Escalating operator feedback: "when you hand me something it's a failure... do the work." The AWS OIDC provisioning was 100% within my admin creds; only the gpg-gated workflow push was genuinely human.** | **Test constraints empirically before declaring "blocked" — attempt the operation, show the actual rejection, THEN reach for the human-gated path. Verify own capabilities first (`gh auth status` for token scopes, `aws iam list-attached-user-policies` for perms, or just try it). Do the maximum yourself; reduce the operator to the irreducible atom (e.g. the gpg passphrase ADR-0216 genuinely requires). Never hand a script for work you haven't proven you can't do.** |
| 2026-07-08 | **`provision.sh` re-applies the full Lambda env on every deploy, sourcing `CLOUDFLARE_ORIGIN_SECRET` via `... \|\| echo ""` (line 40) — re-running it during a transient SSM read failure would silently blank the just-verified origin secret and re-open the #764 fail-open.** | **For a code-only fix, deploy with a targeted `aws lambda update-function-code --function-name AletheiaAgent` (no config re-apply), NOT full `provision.sh`. | 2026-07-07 | **Made local edits (cross-links, footer) on an `Aletheia.wiki` checkout a month stale (`origin/master` 3 ahead); the "drift" I was about to document in Security/Privacy had already been fixed upstream by the audit-10817 remediation. Caught only by inspecting ahead/behind before pushing.** | **`git fetch` + check ahead/behind on ANY repo (wikis included) before editing, and re-ground findings against the pulled base. A stale checkout produces confidently-wrong claims — especially dangerous for a CISO-facing artifact.** |
| 2026-07-08 | **Created a subdir `Aletheia/` inside a PRIVATE tooling repo (per "make a directory for Aletheia there"); the path `<private-repo>/Aletheia/tools/` read like the public Aletheia repo and alarmed the operator into thinking a security tool had leaked public.** | **Don't name a subdir after a public repo inside a private one — the path becomes ambiguous about which repo it lives in.
